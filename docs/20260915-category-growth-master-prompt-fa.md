# پرامپت مادر بهینه‌سازی دسته‌های کشاورز بیست — 2026-09-15

## مأموریت
تمام دسته‌های فروشگاه کشاورز بیست را به‌صورت مرحله‌ای، داده‌محور و بدون کار تکراری بررسی و بهینه کن؛ هدف هم‌زمان افزایش کیفیت انتخاب مشتری، نرخ کلیک ارگانیک، شانس رتبه‌گیری، قابلیت استناد در موتورهای پاسخ و نرخ تبدیل است. هیچ صفحه‌ای را فقط برای افزایش تعداد کلمات بازنویسی نکن.

## قوانین غیرقابل مذاکره
1. ابتدا وضعیت زنده صفحه، Search Console و محتوای فعلی را بخوان؛ سپس یکی از چهار تصمیم KEEP / SURGICAL / REWRITE / TECHNICAL را ثبت کن.
2. دسته‌های CLOSED/PASS را دوباره بازنویسی نکن مگر یک ایراد جدید و مستند کشف شود. فریز فعلی: 745، 749، 756، 761، 767، 792، 825، 826.
3. URL، slug، parent، canonical، وضعیت ایندکس یا Redirect سالم را بدون دلیل مستند تغییر نده.
4. قیمت، تخفیف، موجودی، کاربر، نقش و تنظیمات پرداخت خارج از محدوده هستند.
5. هیچ فشار کاری، دبی، قطر، مقدار مصرف، سازگاری، برند، استاندارد یا ویژگی فنی را حدس نزن.
6. محتوای قابل مشاهده فقط با نام «کشاورز بیست» نوشته شود.
7. لحن فارسی طبیعی، متخصص، روشن و مشتری‌پسند باشد؛ از کلیشه، تکرار کلیدواژه، مقدمه طولانی و فشار فروش پرهیز کن.
8. هر Write از مسیر GitHub Guarded Gateway انجام شود و پس از آن Readback واقعی بگیر.

## منطق اولویت‌بندی
امتیاز هر دسته را از این عوامل بساز:
- Impression و Click واقعی Search Console؛
- جایگاه 3 تا 15 و CTR ضعیف = فرصت سریع؛
- نیت تجاری و ارزش تکمیل سبد؛
- تعداد محصول و اهمیت معماری؛
- ضعف واقعی متن یا UX، نه صرفاً طول کم؛
- Cannibalization، Redirect، Canonical و صفحات پارامتری؛
- Missing ALT، فیلتر نامناسب یا نبود ویژگی تصمیم‌ساز.

## الگویی که از فروشگاه‌های قوی باید اقتباس شود، نه کپی
- راهنمای انتخاب قبل از خرید بر اساس سناریوی واقعی مشتری؛
- فیلترهای مخصوص همان دسته و مرتب‌سازی معنی‌دار؛
- مقایسه مدل‌ها و سایزها بر اساس کاربرد؛
- چک‌لیست «چه چیزهایی همراه این خرید لازم است؟»؛
- سبد یا کیت کامل شامل قطعات مکمل سازگار؛
- توضیح ریسک انتخاب اشتباه بدون ترساندن؛
- FAQ مبتنی بر Query واقعی؛
- CTA برای سفارش آنلاین، استعلام یا پیش‌فاکتور کامل؛
- لینک داخلی به دسته‌های مکمل و راهنمای آموزشی؛
- نمایش محدودیت و اطلاعاتی که قبل از انتخاب باید اندازه‌گیری یا تأیید شوند.

## قالب استاندارد هر دسته
### بالای لیست محصولات
60 تا 120 واژه: دسته چیست، برای چه کسی است، مهم‌ترین معیار انتخاب چیست، و مشتری از همین صفحه چه کاری می‌تواند انجام دهد. متن طولانی نباید محصولات را به پایین هل بدهد.

### بخش راهنمای پایین/میان صفحه
1. راهنمای سریع انتخاب؛
2. تفاوت مدل‌ها/سایزها/خانواده‌ها؛
3. جدول یا لیست مقایسه فقط اگر داده واقعی وجود دارد؛
4. چک‌لیست قبل از خرید؛
5. اقلام مکمل و سبد کامل؛
6. نصب/نگهداری فقط در حد معتبر و مرتبط؛
7. اشتباهات رایج؛
8. FAQ واقعی؛
9. CTA مشورتی و پیش‌فاکتور.

## کنترل SEO / GEO / Conversion
- یک H1؛ H2/H3 منظم؛
- Title و Meta متناسب با Query و بدون وعده‌ای که صفحه برآورده نمی‌کند؛
- Canonical self برای صفحه اصلی دسته؛
- Indexable بودن فقط برای صفحات دارای ارزش جست‌وجویی؛
- Schema موجود با محتوای صفحه متناقض نباشد؛
- لینک داخلی طبیعی به Parent، Child، مکمل و محتوای آموزشی؛
- ALT واقعی تصاویر؛
- هیچ FAQ ساختگی برای Schema تولید نکن؛
- Query-to-page mapping را بررسی کن و صفحات رقیب داخلی را ادغام/متمایز کن، نه اینکه متن مشابه بسازی؛
- محصول و فیلتر باید زود دیده شوند؛ متن نباید مانع خرید شود.

## چرخه اجرای هر دسته
1. Snapshot زنده: ID، نام، slug، parent، count، description، Title، Meta، H1، canonical، indexability، Schema، ALT و زمان پاسخ.
2. Search Console: 180 روز + 28 روز؛ Queries، Pages، CTR، Position، Cannibalization.
3. محصولات واقعی دسته و ویژگی‌های قابل‌فیلتر را استخراج کن.
4. Intent را به Primary / Secondary / Buying concerns / Complementary basket تقسیم کن.
5. متن فعلی را از نظر Human Style، تکرار، فنی‌بودن، قابلیت اسکن، فروش و FAQ امتیاز بده.
6. اگر امتیاز کافی است KEEP؛ اگر ضعف محدود است SURGICAL؛ فقط در ضعف بنیادی REWRITE.
7. تغییر را با حداقل سطح لازم انجام بده.
8. Readback و Crawl پس از تغییر؛ identity fields و URL باید دست‌نخورده بمانند.
9. تغییر را با تاریخ و شواهد ثبت کن.
10. نتیجه را بعداً با Search Console مقایسه کن؛ رشد را تضمین نکن.
