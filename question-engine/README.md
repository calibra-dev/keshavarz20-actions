# Customer Question Engine

این موتور برای تولید و ثبت پرسش‌های پیشنهادی خریداران روی محصولات کشاورز بیست طراحی شده است.

## وضعیت انتشار

- پیش‌فرض: غیرفعال (`enabled=false`).
- تست دستی `submit_one` فقط یک دیدگاه با نویسنده ثابت «پرسش پیشنهادی خریداران» و وضعیت `hold` ثبت می‌کند.
- زمان‌بندی تولیدی فقط پس از تأیید تست اول فعال می‌شود.
- در حالت فعال، فاصله هدف بین دو سؤال 1080 تا 1559 ثانیه است. Workflow هر 15 دقیقه بیدار می‌شود و اگر زمان دقیق در پنجره بعدی باشد تا timestamp هدف sleep می‌کند؛ تأخیر احتمالی خود GitHub Actions می‌تواند زمان واقعی را عقب بیندازد.

## اصول

- انتخاب متوازن از کل محصولات منتشرشده؛ محصولات کم‌سؤال در اولویت‌اند.
- تشخیص خانواده: کود/سم، نوار تیپ، لوله، شیر، اتصال، فیلتر، تزریق کود، آبپاش و عمومی.
- سناریوهای کشاورزی: زراعت، صیفی، جالیزی، باغ مثمر، گیاه زینتی و آپارتمانی، خاک، آب، فصل/مرحله رشد، شیب، دبی، فشار، طول مسیر و روش آبیاری.
- سؤال‌های تجاری: خرید عمده، قیمت روز، تخفیف، ارسال شهری/باربری و اقلام مکمل.
- سؤال‌های Problem-first و Post-purchase: زردی، نشتی، افت فشار، گرفتگی، نتیجه نگرفتن و تغییر غرقابی به قطره‌ای.
- 15٪ هدف لحن عامیانه طبیعی؛ بدون غلط‌سازی عمدی یا تحقیر زبان روستایی.
- 70٪ هدف وجود سلام/تشکر/درخواست محترمانه.
- هیچ دوز، سازگاری، فشار، اثر یا ادعای فنی تأییدنشده به‌عنوان واقعیت در سؤال ساخته نمی‌شود.
- سؤال‌های سیستم با نام ثابت مشخص می‌شوند؛ هویت مشتری جعلی تولید نمی‌شود.
- سؤال‌های تولیدی امتیاز کیفیت می‌گیرند و زیر آستانه منتشر نمی‌شوند.

## حافظه بدون دیتابیس جدا

تاریخچه از دیدگاه‌های واقعی وردپرس با نویسنده ثابت همین موتور بازسازی می‌شود. این کار از هزاران commit حالت در GitHub جلوگیری می‌کند. انتخاب محصول، فاصله اجرا و کنترل تکرار از تاریخچه دیدگاه‌ها مشتق می‌شود.
